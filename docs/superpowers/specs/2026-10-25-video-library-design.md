# 视频库

## 产品范围

独立的视频库模式，入口 `/videos`。保持聊天、媒体墙、文章和频道未读的现有语义。仅纳入主媒体为普通视频或 MIME 为 video/* 的文件；排除 GIF、圆形视频、评论和 Telegraph 内嵌媒体。同一 Telegram 帖子中的视频自动组成合集；分组键包含会话、来源、原频道和媒体组，防止不同来源的同号媒体组碰撞。单个视频显示单视频卡片。

## 界面

视觉沿用现有主题 token、24px 浮岛、圆角按钮、系统字体和响应式行为；浅色蓝、深色紫跟随现有主题。已确认的交互示意见服务器仓库 `visualizations/tgarchive-video-library.html`。视频库拥有专用导航和内容区，页面包含继续观看、最近入库和帖子合集；支持全部/单视频/合集、来源会话、观看状态、收藏、标签、关键词与排序。筛选写入查询参数，回退恢复滚动位置。

卡片使用 16:9 封面，显示标题、来源、时长或合集数量、观看进度。标题默认来自帖子首个非空说明首行、文件名或“未命名视频”，可单独修改而不改变消息原文。多视频详情按 Telegram 消息号、媒体 position 和消息 ID 稳定排序。图片混合帖子只展示视频，并保留帖子的完整说明。

## 播放

详情页提供继续播放、收藏、标签、原帖和原文件下载。独立播放页使用现有 Vidstack 播放器及兼容副本选择逻辑，旁边显示当前合集队列。自动下一条仅限当前合集，可关闭；合集中不可播放的条目保留状态，自动播放跳过不可用条目。原帖跳转使用应用内定位，不主动标记频道已读。

进度按 media_id 在 SQLite 保存，共享给当前单人实例所有设备。播放时节流写入，暂停、离开、后台时尽力保存；元数据/恢复时不把初始 0 覆盖已有进度。看完保留已看状态，续播从 0 开始。手动已看/未看独立于频道未读。保留现有浏览器音量、静音、倍速偏好。写入失败显示提示且允许继续播放。

## 数据与查询

先聚合完整帖子，再对聚合项分页，分页不会拆开相册。列表只加载当前页及首页各分区的小页；详情按需加载。分组包含所有有效同帖消息以取得图片上的说明和已有收藏，视频列表只含符合范围的主媒体。收藏及标签以规范帖子消息关联现有 favorites；当前相册中已有其他成员的收藏仍纳入过滤。复用现有媒体与缩略图，缺缩略图由后台 ffmpeg 工作线程生成 JPEG，可选合集内视频为封面。

新增迁移存观看进度与视频库标题/封面选择，原始媒体保持原路径。新增 API 均沿用现有鉴权、Host 和 JSON/Origin 写请求保护。查询参数和进度校验错误返回 400，已删除/非视频对象返回 404。删除原消息后条目/进度不再通过库接口暴露。媒体状态变化、消息新增/删除、收藏变化与重连更新库视图。

## 验收

测试覆盖跨来源分组隔离、混合相册说明、先聚合后分页、中文/文件名检索、排序游标、评论排除、收藏标签、进度校验和持久化。前端覆盖路由、返回、加载/空/失败态、筛选防竞态、播放器恢复/保存/销毁、合集内自动下一条。运行全部 Go 与前端测试及 production build；浏览器验收桌面与 375px、浅色与深色、直接打开详情与刷新。NAS 部署遵循只使用正式 release 的现有约束，schema 升级前须备份。
